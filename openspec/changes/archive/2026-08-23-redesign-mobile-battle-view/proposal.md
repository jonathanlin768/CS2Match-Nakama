## Why

当前 BattlePage 主要通过隐藏桌面阵容和缩小间距适配手机，导致移动端信息层级松散、阵容状态缺失、地图与播报割裂，并且雷达底图缩放后事件标记可能偏离实际地图位置。需要为移动端建立独立但共享同一回放状态的比赛视图，使约 390px 宽的手机屏幕也能清楚呈现比分、回合、雷达、存活状态和最近事件。

## What Changes

- 为 BattlePage 增加移动端专用信息架构，不再把桌面三栏布局简单压缩或只隐藏两侧阵容。
- 将移动端比分、回合状态、回放控制、炸弹状态、雷达、双方存活状态和紧凑事件流组织为连续的比赛舞台。
- 为阵容、地图/实时战况和数据统计提供移动端可切换入口，避免辅助信息在小屏幕上直接消失。
- 将雷达底图和击杀、炸弹等事件标记放入同一个 SVG `viewBox`，使用服务端 `0..1` 归一化坐标渲染，保证不同视口、设备方向和浏览器缩放下位置一致。
- 为移动端提供结构化紧凑事件行，明确显示 T/CT 阵营、选手、武器或事件类型；完整本地化战报仍可访问。
- 保留现有桌面端主要布局和功能，并为约 390px、平板和桌面视口增加响应式及端到端验证。
- 不改变比赛规则、服务端战报、事件顺序、最终统计或状态同步机制。

## Capabilities

### New Capabilities

无。本变更扩展现有 BattlePage 回放能力，不建立重复的移动端独立业务能力。

### Modified Capabilities

- `simu-client-replay`: 补充移动端比赛舞台、紧凑事件流、阵容与统计切换，以及雷达底图和事件标记共享坐标视口的可验收要求。
- `simu-battle-full-replay`: 补充移动端回放过程中当前回合、播放控制、存活状态和辅助视图的展示与交互要求。

## Impact

- **React 前端**：影响 `client/src/pages/BattlePage.tsx`、Battle 组件、响应式样式和前端测试；预计新增移动端布局组件，并复用既有回放控制器和派生状态。
- **Nakama 后端**：无改动；不新增 RPC、Match Handler、Hook 或 Go 依赖。
- **状态同步**：无改动；`MatchReport`、回合快照和事件位置仍为服务器权威状态，客户端只调整表现和导航。
- **Storage / 数据库**：无改动，不新增读写或权限规则。
- **Luban 配置表**：无改动；继续使用现有地图雷达资源、选手资料和战报字段。
- **依赖与部署**：不新增运行时 npm 包；若仓库仍无浏览器端测试框架，则新增 Playwright 测试开发依赖，用于固定视口端到端与截图验证。前端 Docker 镜像需在实现后重新构建验证，部署拓扑不变。

# 这里是一个模拟系统的拆单

1. MVP的MVP： ✅ 已完成
通过编写一个测试的rpc路由发放给客户端，然后客户端在点击匹配的时候发这个测试的协议上来，然后这里准备两套阵容，直接开打。第一波只要能够正常输出战报和统计信息即可。（就打一回合也可以）
目的：
确认进出战斗 战报 数据统计 日志播报 等等的结构和职业选手的配表信息。

2. 接下来两路并进
2.1 战斗外，处理选手战队等信息的配置，数值优化
2.2 战斗内：实现回合推演、地图分路、战斗流程、统计、击杀点展示、日志播报等细节

2.2.1 单回合推演引擎
- 路线自动选择与分配（主路线随机 + 30% 概率附加副路线、夹击加成）
- CT 防守侧重自动分配（重 A / 重 B）及防守选手分路
- 位置标签加成（突破手、狙击手、指挥、自由人、补枪手、守点者）
- 对决演算引擎（命中判定、伤害计算、护甲减伤、补枪、残局加成）
- 下包 / 回防 / 拆包状态机与胜负判定
- 模拟时间生成（推进时间、首杀时间、后续击杀、下包、回防、最终校正）

2.2.2 整场比赛状态机
- 多回合循环与比分累计
- 12 回合后攻守换边
- 先到 13 分获胜；24 回合平后进入加时（先到 16 分，每 6 回合换边）

2.2.3 事件、统计与展示
- HLTV 事件生成与特殊播报前缀（首杀、爆头、多杀、残局）
- 回合统计与整场比赛统计（K/D、ADR、FK、MK、KAST 等）
- 客户端地图击杀点展示
- 实时数据面板与战后统计界面
2.3 新定义一个正式的匹配rpc路由接口，接通Nakama的匹配系统，由nakama分配对手，走正式的接口进行战斗计算

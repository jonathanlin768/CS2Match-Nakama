# 14 · 前端回放：从 JSON 到 BattlePage

> 换到客户端。这一篇回答：一份几十 KB 的战报 JSON，是怎么变成"一秒揭示一个事件"的比赛回放的？以及一个贯穿前后端的原则——**客户端只是观众，永远不是裁判**。
>
> 前置依赖：03（端到端旅程）。

## 1. 入口：一场比赛如何"到达"回放页

前端调用链（第 3 篇见过）：

```tsx
// MatchPage.tsx（电脑对战）与 TutorialPage.tsx（教学）同款逻辑
const report = await simuMatch(session, { mode: "computer" })
navigate("/battle", { state: { report } })
```

- `client/src/api/simu.ts#simuMatch` 调 Nakama 的 `SimuMatch` RPC，把 JSON 解析成 `MatchReport` 类型（同文件还保留了 `debugSimuMatch`，对应第 3 篇的调试 RPC；两者都经 `callMatchRpc` 用 `client.rpc` 发请求并 `JSON.parse` 响应）；
- 路由在 `client/src/main.tsx`：`{ path: "/battle", element: <BattlePage /> }`；
- `BattlePage` 通过 `useLocation().state` 拿到 report——**比赛结果通过路由状态传递，页面不重新请求、不重新计算**。

一个 React 知识点顺带说明：`useLocation` 是 react-router 的 hook，路由跳转时携带的数据存在浏览器内存里（刷新页面会丢，这是当前实现的已知限制，未做持久化恢复）。

## 2. 类型契约：前端眼中的比赛

`client/src/types/match-report.ts` 定义了一套与后端 JSON 一一对应的类型。记四个核心结构：

| TS 类型 | 对应后端 | 关键字段 |
|---------|---------|---------|
| `MatchReport` | `MatchResult` | `match_info`、`rounds[]`、`final_stats`、`winner_team_id`、`debug_enabled` |
| `RoundReport` | `RoundResult` | `round_number`、`team_t_id/team_ct_id`、`score_team_a/b`（队伍身份）与 `score_t/ct`（阵营投影）、`events[]`、`player_states[]`、`bomb` |
| `GameEvent` | `GameEvent` | `timestamp`（秒）、`event_type`（共 22 种）、`attacker/victim`、`weapon`、`location{x,y,name}`、`reason`、`bomb`、`state`（快照） |
| `PlayerState` | `PlayerState` | `player_id`（**本场实例 ID**，整场唯一，作状态键）、`config_player_id`（策划表 ID，仅展示/查表用）、`hp`、`alive`、`kills/deaths`、`weapon{primary,has_kit,...}` |

两个字段值得点名：

- **`event.state`**：每个事件携带的"当时世界快照"（第 13 篇的 `snapshotForEvent`）——`EventStateSnapshot` 含四类：比分（team/t 两套）、`players[]`、`bomb`、`controls[]`。前端做"事件级回放"全靠它。
- **`debug_enabled`**：由后端的 `BattleReportDebugLog` 配置键控制（第 3 篇）。为 true 时，`BattlePage` 会在 console 打印整场战报、逐回合事件表、最终统计（`BattlePage.tsx#logFullMatchReport`）——学习引擎最好的调试入口之一。

## 3. 五个纯函数：回放的核心算法

`client/src/pages/battle-playback.ts` 是整条前端链路的"大脑"，五个导出函数全部是**纯函数**（同样的输入 → 同样的输出，不碰 DOM、不碰网络）：

### 3.1 authoritativeScoreAtPlayback（比分）

```ts
export function authoritativeScoreAtPlayback(report, round, roundIndex, events) {
  const hasRoundEnd = events.some((event) => event.event_type === "ROUND_END")
  if (hasRoundEnd) return { teamA: round.score_team_a, teamB: round.score_team_b }
  return previousTeamScore(report, roundIndex)   // 上一回合结束时的比分
}
```

这正是第 5 篇"比分权威性"在前端的镜像：**读 `score_team_a/b`（队伍身份），而不是 `score_t/ct`（阵营）**。换边后 T/CT 字段会"对调"，但队伍字段永远跟着队伍走。播放中的比分规则：本回合的 `ROUND_END` 事件还没揭示前，显示上一回合的比分——**比分只在服务器宣布回合结束时跳变**，客户端不提前"猜"。

### 3.2 latestBombAtPlayback（炸弹）

从可见事件**倒序**找最近一个带炸弹快照的事件（`event.bomb ?? event.state?.bomb`），找不到就用回合开局的 `round.bomb`。倒序扫描保证拿到的是"播放到此刻"的最新炸弹状态。

### 3.3 playerVitalsAtPlayback（血量）

以回合开局的 `player_states` 为底（全员满血），按可见事件重放：`DAMAGE` 事件扣血（`extra.damage`，缺失时回退到事件快照里的 HP）、`KILL` 事件直接置 0。**血量是"算"出来的，不是服务器推流下来的**——回放 = 事件前缀的确定性重放。

### 3.4 cumulativePlayerStatsAtPlayback（累计数据）

K/D/A 从两个来源累加：之前所有回合的完整事件 + 当前回合已揭示的事件。`KILL` 事件的 `attacker/victim` 各记一票，`extra.assist_ids`（第 12 篇的助攻名单）给每个助攻者记一次助攻。

### 3.5 selectedRoundInitialEventCount（切回合的起点）

手动点击某个回合时，先揭示到该回合的 `ROUND_START` 事件——让观众先看到"这局谁打 T、用什么战术"（`formatBattleEvent` 对 `ROUND_START` 的文案直接展示 `strategy_template_id` 与 `ct_setup_template_id`）。

**共同点**：五个函数都是"事件前缀 → 派生状态"。这就是第 3 篇说的哲学——前端不重新模拟，只对服务器权威结果做**确定性重放**。这不只是风格，而是规格要求：`openspec/specs/simu-battle-full-replay/spec.md` 明确"客户端 SHALL NOT 重新计算比赛规则或胜者"。

## 4. BattlePage：五状态播放机

`BattlePage.tsx` 用五个 React state 搭出一台播放机：

| state | 含义 | 变化时机 |
|-------|------|---------|
| `roundIndex` | 当前回合 | 自动播放跨回合 / 手动点回合 |
| `furthestRoundIndex` | 已解锁的最远回合 | 播放推进时取 max |
| `visibleEventCount` | 当前回合已揭示事件数 | `setInterval` 每秒 +1 |
| `playing` | 是否播放中 | 暂停/继续按钮 |
| `fullMatchRevealed` | 是否跳过了比赛 | "跳过比赛"按钮 |

核心的 `setInterval`（`BattlePage.tsx` 播放 effect）逻辑：

```tsx
setInterval(() => {
  setVisibleEventCount((count) => {
    if (count < currentRound.events.length) return count + 1      // 本回合还有事件
    if (roundIndex < report.rounds.length - 1) {                   // 跨回合
      setRoundIndex(roundIndex + 1)
      setFurthestRoundIndex((idx) => Math.max(idx, nextRoundIndex))
      return 1
    }
    setPlaying(false); setFullMatchRevealed(true)                 // 全剧终
    return count
  })
}, 1000)
```

每秒揭示一个事件；"跳过比赛"按钮则直接揭示最后一回合的全部事件并置 `fullMatchRevealed`。回合条上未解锁的回合不可点（`visibleRounds = fullMatchRevealed ? all : slice(0, furthest+1)`）——**没"演"到的内容不给看**，这是回放体验的小设计。

对 React 新手的提示：`setVisibleEventCount(count => ...)` 用的是**函数式更新**——基于 React 的最新值计算新状态，而不是闭包里捕获的旧值，所以 interval 不需要每秒重建；`useMemo`（`BattlePage.tsx#playback`）把"当前可见事件 → 比分/数据/血量/炸弹"的推导缓存起来，依赖项变了才重算；`useEffect` 负责副作用（定时器、console 日志），依赖数组决定何时重跑。五个播放 state 变化 → `useMemo` 重算派生状态 → 组件树拿到新 props 重渲染，数据流单向、可预测。

## 5. 组件树：四个观众席

```text
BattlePage
├── Scoreboard   比分板：队名、比分、回合数、阶段标签（半场/换边/OT1·3/6）、胜者
├── TeamRoster ×2 两侧名单：头像、血量、K/D/A、武器（AK-47 展示名映射）、拆弹钳
├── BombWidget   炸弹状态徽章（携带/掉落/已下包/已拆除/已爆炸 + 所在区）
├── MapView       Dust2 雷达图（底图 /csmaps/de_dust2_radar_trans.webp）：只标注带坐标的 KILL/下包/拆包/爆炸事件，left/top = location.x/y × 100%
└── EventFeed    事件流：逐条中文播报（formatBattleEvent，击杀带首杀/补枪标注）+ 双方 K/D/A 统计弹窗 + 自动滚动到底
```

两个实现细节：

1. **展示名映射**（`BattlePage.tsx#buildBattlePlayer`）：后端武器 ID 是 `AK47`，展示层映射成 `AK-47`；`armor` 有甲就显示 100。**引擎的 ID 和 UI 的展示名解耦**，是前后端契约的惯例。
2. **MapView 的坐标**：事件的 `location.x/y` 是服务器算好的 0–1 归一化坐标（第 13 篇的语义采样），前端直接映射到雷达图百分比位置。**坐标是战报的一部分，不是前端临时编的**——同一场比赛每次回放，事件都落在同一个点。

## 6. legacy 与现状：旧页面去哪了

`client/src/legacy/` 下的旧版 `MatchPage`、`RoundEvents` 等已被 `tsconfig.app.json` 的 exclude 排除出构建——是**死代码**，只有 `legacy/components/ui/*`（dialog、button 等通用组件）仍被新的 `EventFeed` 复用。当前活跃链路就是：`api/simu.ts → BattlePage → components/battle/*`。读前端代码时以 `client/src/components/battle/` 和 `pages/BattlePage.tsx`、`pages/battle-playback.ts` 为准，legacy 目录可以跳过。

## 7. 动手实验：用 console 对照学内核

推荐的组合拳：

1. 确认 `#CombatConst` 里 `BattleReportDebugLog = true`（或在临时改动后重新导出配置，第 4 篇的流程）；
2. 进一场电脑对战，打开 DevTools Console；
3. 观察 `[SimuMatch]` 分组：整场战报 → 每回合的 `round` 快照 → 事件表（含 `reason.code`）→ 最终统计；
4. 播放时逐事件对照 `[SimuMatch][播放][R1][3/57]` 日志与界面变化——**把第 12 篇的脉冲结算、第 13 篇的炸弹投影，在浏览器里亲眼再看一遍**。

这比读一百遍文档都管用。

## 本篇回顾

- 比赛结果经路由 state 传到 BattlePage；前端不重新请求、不重新计算。
- 五个纯函数 = "事件前缀 → 派生状态"；比分读队伍身份字段、血量靠事件重放。
- 五状态播放机：每秒揭示一个事件，未解锁回合不可点。
- 坐标、文案、展示名全部来自服务器权威数据，客户端只是观众。
- legacy 目录是死代码，活跃链路在 `components/battle/`。

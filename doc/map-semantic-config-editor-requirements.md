# 地图语义配置编辑器需求文档

## 1. 背景

`simuMatchDesign.md` 中的地图语义配置包含点位、区域、路径、视野、风险点、路线等空间信息。这类信息如果直接维护在 Excel 中，配置成本高、难校验、难预览，也不利于调试击杀坐标、转点路径和高低关系。

需要提供一个本地可视化编辑器，让设计者基于地图雷达图配置地图语义，并将结果导出为现有 Luban 配表流程可消费的数据。

具体地图语义字段、表结构和引擎消费方式以 `doc/simuMatchDesign.md` 的 **2.2 地图配置表** 为准。本需求文档只定义编辑器的功能范围、输入输出和交互目标。

## 1.1 规范来源

编辑器的导出目标不是自定义格式，也不是泛用地图数据格式，而是 `doc/simuMatchDesign.md` 的 **2.2 地图配置表** 章节所定义的地图语义配置。

执行者实现导出、校验和对象模型时，必须先阅读并对齐：

```text
doc/simuMatchDesign.md
  -> 2.2 地图配置表
```

如果本需求文档与 `simuMatchDesign.md` 的 2.2 章节存在冲突，以 `simuMatchDesign.md` 的 2.2 章节为准。

## 2. 目标

- 降低地图语义配置成本。
- 让点位、区域、路径、视野关系可以在雷达图上直观编辑。
- 支持配置击杀点随机偏移所需的采样区域。
- 支持表达地图高低层级关系，例如 A 小到 A 包点、警家之间的一楼二楼关系。
- 在导出前发现配置错误，避免错误数据进入模拟器。
- 输出可进入 Luban 导表链路的配置文件。

## 3. 非目标

- 不做真实 3D 地图编辑器。
- 不自动识别地图结构。
- 不自动生成完整寻路网络。
- 不模拟真实弹道、投掷物轨迹或连续视野传播。
- 不做线上多人协作编辑。
- 不替代 Luban，只作为地图语义数据的可视化生产工具。

## 4. 使用对象

- 玩法设计者：配置点位、路线、区域和视野语义。
- 程序开发者：校验配置是否能被模拟器稳定消费。
- 前端开发者：预览战报坐标、击杀点和地图标记效果。

## 5. 输入

编辑器第一版需要支持以下输入：

- 地图雷达底图，例如 `client/public/csmaps/de_dust2_radar_trans.webp`。
- 地图工程文件，用于保存编辑器自己的工作状态。
- 已存在的地图语义配置，用于继续编辑。
- `simuMatchDesign.md` 中定义的地图语义模型约束。

地图工程文件应保存编辑状态，例如图层可见性、对象选择、草稿对象、画布缩放、辅助标记等。这些内容不一定导出给 Luban。

## 6. 输出

编辑器需要输出两类文件：

| 输出 | 用途 |
|---|---|
| 地图工程文件 | 作为编辑器的源文件，方便继续编辑、审查和版本管理 |
| Luban 配表文件 | 对齐 `simuMatchDesign.md` 2.2 地图配置表，作为现有配置导出流程的输入 |

导出的配表文件只承载模拟器需要消费的地图语义数据。具体文件名、字段、枚举和表结构不在本需求文档中展开，以 `simuMatchDesign.md` 的 **2.2 地图配置表** 和后续 OpenSpec 规格为准。

## 7. 核心工作流

```text
打开地图工程
  -> 加载雷达底图
  -> 编辑点位 / 区域 / 路径 / 视野 / 路线
  -> 运行配置校验
  -> 对齐 simuMatchDesign.md 2.2 地图配置表
  -> 预览坐标与语义效果
  -> 保存工程文件
  -> 导出 Luban 配表
```

编辑器应允许先保存草稿；只有导出时才要求通过强校验。

## 8. 功能范围

### 8.1 地图工程管理

- 新建地图工程。
- 打开已有地图工程。
- 保存地图工程。
- 设置地图 ID、地图名称、底图路径和地图版本。
- 配置雷达图显示比例和坐标归一化规则。

### 8.2 画布操作

- 显示雷达底图。
- 支持缩放、平移、居中和重置视图。
- 支持对象选中、拖动、复制、删除。
- 支持撤销和重做。
- 支持网格、坐标、吸附和辅助线。

### 8.3 图层管理

编辑器至少需要以下语义图层：

- 点位层。
- 区域层。
- 路径层。
- 视野层。
- 路线层。
- 风险点层。

每个图层应支持显示、隐藏、锁定和颜色区分。

### 8.4 点位编辑

- 在地图上创建点位。
- 拖动点位位置。
- 编辑点位名称、类型、区域归属和阵营倾向。
- 标记点位所在层级，例如地面、高台、坡道、楼梯。
- 将点位关联到区域、路径和路线。

### 8.5 区域编辑

- 绘制多边形区域。
- 调整区域顶点。
- 设置区域用途，例如击杀采样、包点、控制权、交火、风险。
- 将区域关联到一个或多个点位。
- 支持预览区域内的随机采样点。

击杀坐标不应只依赖点位中心。编辑器应允许为关键点位配置采样区域，以便战报展示时生成自然的随机偏移。

### 8.6 路径编辑

- 连接两个点位形成路径。
- 编辑路径方向性。
- 配置路径的语义信息，例如耗时、风险、暴露、移动方式。
- 在路径上添加中途风险点。
- 预览路线连通关系。

### 8.7 视野编辑

- 配置点位之间、点位与区域之间的可见关系。
- 支持单向和双向视野。
- 支持配置距离、遮挡、角度优势和暴露风险。
- 支持表达高低关系，例如高打低、低打高、同层、被高度遮挡。

高低关系不要求真实 3D 建模，但必须在 UI 中有清晰可见的语义表达。

### 8.8 路线编辑

- 将多个点位串联为路线。
- 预览路线经过的点位、区域和风险点。
- 标记路线阵营、目标区域和战术用途。
- 检查路线是否断裂。

### 8.9 校验

编辑器必须提供导出前校验：

- 引用对象不存在。
- ID 重复。
- 路线断裂。
- 关键点位缺少必要坐标或关联区域。
- 区域多边形非法。
- 路径方向配置冲突。
- 视野关系缺少必要语义。
- 高低层级关系配置不完整。
- 导出数据无法满足 `simuMatchDesign.md` 2.2 地图配置表的模型约束。

校验结果需要能定位到具体对象，并在画布上高亮。

### 8.10 预览

编辑器需要提供轻量预览能力：

- 击杀点随机采样预览。
- 路线连通预览。
- 视野线预览。
- 高低关系预览。
- 导出数据摘要预览。

预览只用于检查配置是否自然，不需要运行完整模拟器。

## 9. UI 设计目标

编辑器应是工作型工具，不做营销式页面。

布局建议：

```text
顶部工具栏：选择工具、点位、区域、路径、视野、路线、导出
左侧面板：地图工程、图层、对象列表
中间画布：雷达图和可编辑语义对象
右侧面板：当前对象属性
底部面板：校验结果、预览输出、导出日志
```

交互目标：

- 常用操作不超过两步。
- 选中对象后右侧立即显示可编辑属性。
- 错误配置必须能从错误列表跳转到对象。
- 图层颜色和符号稳定，避免看图时混乱。
- 高低层级必须在视觉上可区分。
- 坐标显示使用归一化坐标，便于前端战报展示。

## 10. 技术栈建议

第一版建议做成本地 Web 工具，直接复用项目现有前端技术栈。

推荐：

```text
React 19
TypeScript
Vite
Konva / React-Konva
Zustand
Zod
ExcelJS
```

选择理由：

- 项目已有 React、TypeScript、Vite，团队上下文一致。
- Konva 适合点位拖动、多边形编辑、连线和图层管理。
- Zustand 足够支撑编辑器状态管理。
- Zod 可用于工程文件和导出数据校验。
- ExcelJS 可在 Node 或浏览器侧生成 Luban 所需 Excel 文件。
- Windows 开发环境下运行成本低，不需要额外桌面客户端。

建议放置位置：

```text
tools/map-semantic-editor/
```

第一版运行方式：

```text
npm run map-editor
```

如果后续需要直接读写项目目录，可增加一个轻量 Node 本地服务。只有当文件系统集成、窗口体验或离线分发成为明确需求时，再考虑 Electron 或 Tauri。

## 11. 第一版验收标准

- 能加载沙二雷达底图。
- 能创建、编辑、保存地图工程文件。
- 能编辑点位、区域、路径、视野和路线。
- 能表达并可视化高低层级关系。
- 能为点位配置击杀采样区域，并预览随机点。
- 能执行导出前校验，并定位错误对象。
- 能导出 Luban 配表文件。
- 导出的 Luban 配表语义与 `simuMatchDesign.md` 2.2 地图配置表一致。
- 导出的配置能进入现有导表流程。
